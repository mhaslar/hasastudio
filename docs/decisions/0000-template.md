# NNNN — Short title in the imperative

- **Status:** Proposed | Accepted | Superseded by [NNNN](NNNN-title.md) | Rejected
- **Date:** YYYY-MM-DD
- **Phase:** N
- **Decided by:** agent | human review | both
- **Affects:** crates or subsystems touched

## Context

What situation forced a decision. Include the constraint that actually binds — hardware, licence, a spec requirement, a measurement. If there is a number, give the number.

Do not write "we needed to choose a library." Write what the choice had to satisfy and why the obvious option did not.

## Options

### A — Name

What it is, in a sentence or two. Then what it costs and what it buys.

### B — Name

Same. Include the option you rejected even if it was obviously wrong — the reason it was wrong is the useful part, and someone will propose it again in four months.

## Decision

The option chosen, stated plainly. Then why, in terms of the constraint from Context.

## Consequences

What this makes easy. What it makes hard or impossible. What now has to be true elsewhere in the codebase for this to keep working — this is the part future readers actually need.

If the decision introduces debt, say so explicitly and say what would trigger paying it down.

## Verification

How we know this was implemented as decided: the test, the benchmark, the assertion. If there is none, say why not.

## Revisit when

The condition that should make someone reopen this. "Never" is a valid answer; leaving it blank is not.
